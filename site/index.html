How it works

  • A Token ACL mint uses DefaultAccountState = Frozen, so every token account starts frozen.
  • A holder unlocks their own account with Token ACL's thaw_permissionless. Token ACL asks ThawGate, which reads the mint's policy: a live SAS attestation for the wallet, the issuer's blacklist, the issuer's allowlist. Anyone can pay; the issuer signs nothing.
  • A holder who stops complying (credential revoked or expired, blacklisted, or below a tightened policy) becomes freezable by anyone, and the keeper freezes them.
  • No transfer hook. The check runs once per account, at thaw. After that a transfer is plain Token-2022: 3,557 CU on an sss-token Token ACL mint, against 27,627 CU with the SSS transfer hook (localnet, LOG S6b).
  • Every decision is logged as TG:ALLOW:<CODE> or TG:DENY:<CODE>, and explain() gives the same reason before anything is sent.

While the project is being judged

Keeper: a sweep scheduled every 10 minutes

No keeper runs continuously. A GitHub Actions job is scheduled to run it every 10 minutes for 150 s over every mint gated by ThawGate, yours included. So a holder who stops complying is frozen at the next run: within about 10 minutes plus GitHub's start delay, which GitHub doesn't bound. A keeper that runs all the time freezes in about 2 s (KEEPER.md).

Status (2026-10-06 16:53 UTC): GitHub started 1 scheduled run in the 9.6 h since the schedules were added, so the sweep is also dispatched by hand, and reserves are re-posted manually daily during judging (KEEPER.md).

Anyone can freeze sooner: thawgate freeze-if-invalid --token-account <account>.

Reserves: scheduled every 6 hours, re-posted manually daily

The two demo mints (vUSD and the S9 mint) need a reserve post younger than 24 hours to mint. A job is scheduled to re-post them every 6 hours, signed by their attestor key, which holds no other authority. GitHub may delay or skip scheduled runs, and it hasn't started this one yet, so the reserves are re-posted manually daily during judging.

Quickstart (devnet)

One script, from a fresh wallet: your own test KYC credential, a stablecoin gated by it, a holder refused, attested, unlocked, minted to, revoked and frozen. Every step is a real devnet transaction. Node 20 or 22. 

mkdir thawgate-quickstart && cd thawgate-quickstart
npm init -y
npm i @thawgate/sdk @solana/web3.js
curl -O https://raw.githubusercontent.com/AryaSingh22/thawgate/main/sdk/examples/quickstart.mjs
node quickstart.mjs

The first run creates issuer.json and asks the faucet for SOL; if it refuses, send the printed address 0.2 devnet SOL from faucet.solana.com and run it again. It ends with done.
